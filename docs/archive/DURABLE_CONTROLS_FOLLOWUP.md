# Durable controls and recovery follow-up

2026-11-07. This supersedes the applicable findings in `OPERATIONS_BOUNDARIES_FOLLOWUP.md`; it does not supersede its other limitations. All exercises used synthetic fixtures and locally owned disposable PostgreSQL clusters. No application server, browser, production data, live provider, or deployment was used.

## Implemented boundaries

* **Access-token revocation.** Migration `013_revoke_access_tokens` adds a shared denylist storing SHA-256 token digests and expiry, not bearer tokens. Logout verifies the bearer, commits its digest, and only then reports application-token revocation. Each signed human-token request checks the shared store after signature/expiry validation and before membership resolution. Missing/unavailable storage fails closed with 503; a revoked token returns 401. Test-only `test_token:` fixtures bypass this store and are unavailable outside TEST. The frontend clears local state even on failure and reports when revocation failed. Only the presented access token is revoked; an identity-provider refresh token or other access tokens are not. Existing signed tokens remain usable unless individually revoked or expired. Entries can be removed by a privileged scheduled maintenance process only after token expiry plus a suitable clock-skew margin; no cleanup scheduler is implemented. Database restoration to an earlier point can lose later revocations: invalidate provider sessions/rotate applicable keys as part of incident recovery.
* **Durable extraction reservations.** Tenant-scoped PostgreSQL rows atomically reserve a fixed-minute attempt and a UTC-month estimated maximum before extraction; the database clock defines the buckets. Defaults are `MODEL_MAX_ATTEMPTS_PER_TENANT_MINUTE=30` and `MODEL_RESERVATION_BUDGET_USD_PER_TENANT_MONTH=50`. Every attempt reserves the configured `MANTLE_MAX_DOCUMENT_COST_USD`, rounded up to integer microdollars, even if the document is a scan or the provider fails. The reservation is not refunded after a timeout, lost worker, or rollback after the reservation commit because provider completion may be unknown. Quota denial is recorded as an extraction failure and follows existing bounded job retry behavior. The transaction locks and checks the current lease before reserving; rejected/stale workers cannot commit a result. The rate limit covers authenticated ingestion's extraction attempts, not every HTTP request, PDF parsing, legacy evaluation tools or external provider access. Fixed windows allow bursts at boundaries. This is a limit on configured reservations, **not a hard billing limit**: provider rates/tokenization/other consumers can differ. The legacy `MANTLE_MONTHLY_BUDGET_USD` remains planning metadata, not this control.
* **Backup/recovery.** PostgreSQL export requires repeatable-read or serializable and fails if row security would filter records or if a table cannot be exported. Backup CLI uses repeatable read. Restore rejects incomplete archives, runs PostgreSQL SQL without splitting semicolons inside data, checks restored table counts and composite foreign keys, validates tenant relationships and document hashes, and rolls back database work on a later verification failure. Its database changes and object-store writes cannot be atomic together; use a new isolated target bucket and database. Partial database-only or storage-only restore is reported as `RESTORE_PARTIAL`. Restore CLI requires an explicit target DB (argument or `RESTORE_TARGET_DATABASE_URL`) and, unless skipping storage, an exact confirmation of the configured destination bucket. The existing web backup endpoint still uses the restricted application DB session and is expected to fail rather than claim a full backup; use a separately authorized offline operator with read access to every protected row and a repeatable-read connection. Restore requires separately authorized write privileges; no elevated runtime role was introduced. Storage/version coordination, off-site retention, operator key custody, restore scheduling and provider identity recovery are operational prerequisites, not proven production capabilities. The custom format is not `pg_dump` and must not be treated as a provider-native point-in-time backup.
* **Identity onboarding.** Outside TEST, invitation acceptance requires explicit `IDENTITY_EMAIL_CONFIRMATION_ENFORCED=true`, configured Supabase URL and public key, and a fresh authenticated provider-user response matching the JWT subject and email with `email_confirmed_at`. Missing configuration or provider failure is 503; mismatched/unconfirmed identity is 403. This operator setting is an attestation, not a remote check of the provider's configuration. Supabase's automatic email confirmation must be disabled, because it can mark an unverified email confirmed. Previously provisioned identities are unchanged; existing identity reconciliation and multi-workspace restrictions remain. Removed fabricated `auth.users`/Google-identity SQL from new backups and disabled the unused email-only ID-rewriting helper; neither workspace email nor restored data proves a provider identity.
* **Financial correction.** Editing a line recalculates totals while keeping the existing tax amount; without authoritative re-grounding this cannot be treated as validated tax evidence. The tax arithmetic gate now fails for corrected lines, blocking approval and explaining why. Corrections remain recorded and audited, but re-grounding/revalidation and a supported path to clear the blocker do not exist. Re-ingestion/manual investigation may be required. No tax or FX policy was invented.

The recovery verifier's audit-mutation probe uses the application's ORM listener; by itself it does not independently prove that database-level immutability triggers exist. Schema migrations must be applied to a fresh target before restore. The local restore exercise validates the seeded audit actor, not every identity-provider or storage configuration. No general statutorily correct GST computation, foreign-currency approval, receipt allocation across multiple receipts, or upstream source-freshness guarantee is claimed.
