# Security and functional boundaries follow-up

2026-11-07. This follows, rather than replaces, the production inspection, receipt-commitment follow-up and historical provider acceptance. Existing workspace changes and records were preserved. No browser, deployment, production data or application server was used.

## Findings and decisions

* **High — incomplete platform backup:** table export failures were converted to zero counts. The export now raises an error rather than packaging a supposedly complete database. PostgreSQL exports set transaction-local `row_security=off`: this does not bypass policies, but makes a policy-filtered query fail. Thus an ordinary RLS-constrained application connection cannot silently produce a one-tenant archive represented as a platform backup. A properly authorized, isolated backup/restore process still needs design and end-to-end restore testing. No new elevated database credentials or RLS bypass were introduced. Archive creation is manual; no scheduler or recovery objective is verified.
* **Medium — backup diagnostics:** backup API returns generic errors and logs the exception type; table, auth-summary, storage-list and document-download failures no longer log raw exception text. Other application logging paths have not received comprehensive redaction review.
* **Medium — tenant boundary:** exception reassignment now accepts only an active, assigned-role user within the current workspace; missing, inactive and foreign users are denied without an audit mutation. Successful assignment retains the existing audit event.
* **High functional — currency:** foreign exception amounts previously appeared as INR and contributed to INR totals. Exception responses now preserve the recorded currency and return no INR exposure for those records; dashboard INR aggregates exclude them and expose exclusion counts. Procurement totals exclude foreign/unknown currencies, and inbox, procurement and approval rows show recorded currency without conversion. Approval remains blocked for non-INR invoices. Historical values were not rewritten, and some database fields retain their legacy `_inr` name. Neither exchange rates nor tax rules are inferred.
* **High — sign-out limitation:** the previous endpoint stated that a session was terminated, although it did not revoke JWTs. Its response and sign-out control now say local clearing does not revoke existing access tokens. A stolen valid token can still work until expiry; server-side revocation and identity-provider session management remain unresolved. Configure short appropriate token lifetimes and incident procedures; this is mitigation, not revocation.
* **Source freshness:** invoice review warns that procurement records are workspace snapshots whose source and freshness are not independently verified. No automatic ERP sync, freshness SLA, timestamp guarantee or upstream commitment check has been added.

The line-edit UI sends `If-Match`, and stale supplied versions are checked; the API still permits clients to omit it. Mandatory conditional updates would affect existing integrations and require a compatibility plan. Full field corrections and extraction-blocker clearing are not implemented. Workspace invitation remains subject to identity reconciliation; self-service multi-workspace onboarding/selection remains unfinished. Email ownership depends on the identity provider's configuration: Supabase documents that disabling email confirmation can mark an unverified email confirmed. Verify production identity configuration before use. General GST jurisdiction, tax accounting, credit notes, multiple-receipt aggregation and partial-quantity allocation are unsupported. The receipt-commitment follow-up records the earlier bounded fix.

The queue has a per-tenant pending-upload cap and the model client has per-document input/output preflight estimates and bounded retries. They are not durable multi-worker rate limits or a monthly/tenant spending cap. Provider requests can complete after a worker loses its lease and can still incur charges. External service quotas and alerts are additional controls, not proof of a hard monetary cap. Signed storage URLs remain bearer capabilities through expiry; direct storage rendering does not rehash at display time. Comprehensive secret/history scanning, production configuration validation, distributed load testing and a scoped independent penetration test remain outstanding.

## Sources and tool selection

* [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) and [REST security](https://cheatsheetseries.owasp.org/cheatsheets/REST_Security_Cheat_Sheet.html): distinguish client clearing from server invalidation.
* [PostgreSQL row security](https://www.postgresql.org/docs/17/ddl-rowsecurity.html) and [backup verification](https://www.postgresql.org/docs/17/app-pgverifybackup.html): `row_security=off` raises rather than silently omitting rows, and verification cannot replace a test restore. `pg_verifybackup` is for base backups and is not applicable to this custom archive.
* [Supabase auth testing](https://supabase.com/docs/guides/auth/testing-auth-flows): email confirmation is an identity-provider configuration prerequisite.
* [AWS Bedrock cost tracking](https://docs.aws.amazon.com/bedrock/latest/userguide/cost-management.html) and [invocation logging](https://docs.aws.amazon.com/bedrock/latest/userguide/model-invocation-logging.html): project usage attribution is distinct from enforcement; invocation logging may contain sensitive inputs and does not cover Mantle calls.
* Existing npm audit is appropriate for the installed npm lockfile and was run read-only with lifecycle scripts disabled. [PyPA pip-audit](https://github.com/pypa/pip-audit) is a maintained, Apache-2.0-licensed repository for Python dependency advisories; releases list 2.10.1, but it was unavailable locally and was not adopted or executed. Its scope and limitations must be evaluated in a clean build. Existing targeted PyPI metadata checks are narrower.

Skills applied: Karpathy guidelines for regression-first targeted changes; Impeccable and Vercel React guidance for truthful UI modifications. Graphify was previously consulted for navigation; current code and tests, not its graph or prior summaries, determine findings. No browser-based visual assessment was performed.

No migration or new runtime setting is introduced by this follow-up. The platform backup change intentionally fails when the configured connection cannot see all policy-protected rows; a separate least-privilege backup design and a tested restore are prerequisites before relying on backups. No production readiness, compliance or completed penetration test is claimed.
